# 1.0.1 稳定性修复

日期：2026-11-14

## 已确认根因

1. 5580 HTTP 解析器进入 `MGMT_READ_BODY` 后固定返回“尚未就绪”，导致
   768 KB 壁纸和 1.5 MB 固件请求永远不进入处理函数。小请求因头部和请求体
   在同一次读取中到齐，所以看起来正常。
2. 旧版壁纸流程同步向 P4 推送像素，而 P4 会在网络接收任务中同步擦除 Flash
   60–90 秒。期间 TCP 缓冲被填满，HTTP 服务被一起拖住。
3. App 上传异常时没有释放原生上传任务；iOS 默认后台 `URLSession` 还会在
   超时后继续重试，造成上传失败后界面断联甚至闪退。
4. 旧版 `usb` 状态只检查 P4 TCP 句柄是否存在，没有验证固件心跳，因此会出现
   “USB/Wi‑Fi 都显示在线，但仪表数据不恢复”的假在线状态。

## 修复内容

- 修复 HTTP Body 完成状态判断，大请求可以正常结束并返回响应。
- 大文件接口改为 `202 Accepted`，文件先落到 `/data`，再由主循环异步分段发送。
- 新增 `GET /api/v1/transfer`，返回 `queued/waiting/writing/done/error`。
- P4 擦除或 OTA 分区准备完成后返回 `0xA9/0xAA`，5580 收到确认后才发送数据。
  P4 准备失败时返回 `0xAB`。
- 传输期间暂停普通遥测和心跳写入，避免再次塞满 P4 的 TCP 接收缓冲。
- P4 心跳超过 10 秒未更新时，5580 主动重建 TCP，并重新下发仪表布局和
  CarPlay 状态。
- P4 启动读取有效壁纸分区后显式启用壁纸图层，修复上传成功但画面仍是纯色
  背景的问题。
- iOS 上传任务改为前台会话，异常路径使用 `finally` 释放原生任务。
- App 只有连续 3 次快照失败才显示离线，短时传输占用不会再把连接状态打坏。

## 真机验证

- 已通过 5580 USB 维护通道部署 `uinputd`，旧版保留为
  `/data/uinputd.rollback-20261114`。
- 已通过原有 OTA 通道更新 P4，P4 心跳、USB 链路和仪表布局恢复。
- `/api/v1/health` 返回 200。
- `/api/v1/status` 显示 P4/USB 在线，固件 MD5 更新为
  `A6A26F9A97D87513C42C99E1B85878FC`。
- 768,000 字节完整 Body 可以进入 CRC 校验并正常返回错误，不再挂住 HTTP。
- 1,504,624 字节固件上传返回 202，最终进入 `done`。
- P4 重启期间观察到 watchdog 主动重连，连接随后自动恢复，无需重启 5580。
